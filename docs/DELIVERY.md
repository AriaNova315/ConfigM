# 交付文件清单

以 `scripts/build_delivery.py` 的白名单为准。源码包只包含：

- `app/` 运行源码、HTML、已固定版本的 Alpine.js、本地许可证和资源校验记录。
- `run.py`、Windows 的 `start.cmd`、直接依赖及 Windows 全量锁文件。
- `templates/tpl/` 下 7 个运行模板，以及 `templates/` 下 7 个原始维护模板。
- `resources/ConfigM导入模板.xlsx`，不包含业务记录或公式。
- README、CLAUDE.md、部署/验证手册、原方案和字段说明。
- `scripts/`、`tests/` 和 `build_templates.py`，供维护和独立验证，不参与默认业务初始化。
- 包内 `MANIFEST-SHA256.txt`，按打包时实际文件内容生成。

明确排除：`configm.db` 及伴随文件、`profiles/`、`generated/` 及 old、根目录 test_*.docx、venv/.venv、缓存、日志、Office 锁文件、.claude 本机设置、.env/凭据，以及 Python 安装器和 wheelhouse。当前本机这些文件全部保留，不因打包而删除。

部署人员另行准备 Python 完整安装器和 wheelhouse，不提交到 Git。建议介质分为 source/、python/、wheelhouse/，并保存实际 Python/Windows/浏览器/Office 版本、校验值和 Windows 验收结果。

部署前解压源码 ZIP 到全新可写目录；不要覆盖已有业务安装。部署流程无需重建模板、运行维护脚本、安装 Git、执行数据库迁移或带入开发机数据库。

## 空白 Excel 模板使用

保持 Sheet 名称、第一行列名和列顺序不变，从第 2 行开始填写。模板为输入区设置了文本格式，以保留项目代号前导零、版本和 WBS。日期填写 `YYYY-MM-DD` 文本或实际 Excel 日期；不填写未经重算的公式。

| Sheet | 列顺序 |
|---|---|
| 项目信息 | 项目名称、项目代号、项目组长、配置管理员；仅第 2 行是一份项目的信息 |
| 项目进度计划 | WBS、任务名称、计划开始时间、计划完成时间、关联配置项 |
| 配置项清单 | 序号、配置项名称、配置项标识、版本 |
| 基线组成 | 基线名称、基线标识、基线版本、包含配置项名称、配置项标识、配置项版本 |

项目进度计划：WBS 整数行为阶段；如 `1.1` 行任务名填“配置管理活动”；`1.1.1` 等第三级活动才会识别。任务名支持“入库”“出库”“发布…基线”“配置状态纪实”“配置管理报告”。入库/出库关联列使用配置项名称，或名称与版本直接拼接，多项用中文逗号分隔；不是填写配置项标识。基线组成多项时首行填写基线信息，续行留空前 3 列。

基线发布关联、入库事由和出库原因在解析后的确认窗口补全。空白模板是填写起点，不能作为已有数据的恢复包；导入确认前务必备份。当前导入项目版本按既有逻辑设置为 `0.0`，其他输入/导出规则保持原样。
